# W13: Updates module division

W13 starts from reviewed W12 `cfe3f616`. Updates already owned its implementation
behind the public `Service` and shared `serviceState`; the earlier facade removal
is not a new saving in this pass. This is a compatible structural change.

- `config.go` owns application policy/configuration and defensive copies.
- `contracts.go` retains public results and staged package views; `projections.go`
  retains deliberate provenance and redaction projections.
- `manifest.go` and `signature.go` separate manifest validation and signature
  handling. Field order, tags, nil/empty collections and signing bytes are unchanged.
- `source.go` owns lane identity and configuration; `source_http.go` owns HTTP
  authority/redirect policy and host client selection; `provider.go` loads manifests.
- `selection.go`, `download.go`, `verification.go`, `transfer.go` and `staging.go`
  divide workflow stages while retaining owner/workflow locks and revision checks.
- `artifact_validation.go` retains authoritative manifest binding and fresh staged
  byte verification. File I/O, path validation, versions and safe error reporting
  have focused helpers within this package.
- `lifecycle_contracts.go` separates public lifecycle types from record operations.
  Private records remain beside their unchanged storage codecs in `store.go`.
- `legacy_apply.go` bounds existing constructors, contracts, adapters and callback
  execution; `compatibility_aliases.go` retains existing shorthand public methods.

Two unreferenced private validation wrappers are removed. Five ignored temporary
file removals in DownloadUpdate are redundant with its unconditional deferred
cleanup, which still executes before the workflow lock is released. No other
function-body change is intended. Previous tests remain unchanged.

Independent review compared declarations, imports and initialization behavior
against W12 and found no introduced defect. The signed payload golden vector,
source/channel/policy isolation, authenticated redirect restrictions, public path
redaction, artifact binding, same-size handoff tampering, persistence/cancellation,
callback serialization and record-only lifecycle regressions remain required.

The persistence schema and separate metadata writes are unchanged. Consolidating
repeated persisted manifests, generation commits and migration/recovery belongs
to W14. Context/I/O optimization belongs to W15. Record-only methods still perform
no installation, extraction, restart or legacy callback. File movement alone
establishes neither runtime speed nor binary-size improvement. Hosted/platform
and race qualification, publication and consumer installation remain separate.
